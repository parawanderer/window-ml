Workspace settings — the same widget, open or closed shadow

The panel below is a Web Component. Its shadow-root mode is decided when it's created and can't be changed after — so the toggle rebuilds the element in the mode you pick. Both modes look and click identically to you; the only difference is whether outside JavaScript (and the agent's DOM tools) can reach in. Open panels also nest a second open root (the "Display name" row), so that text is two shadow hops deep.

Current mode: OPEN

Try (OPEN mode) — the agent finds + acts via selectors (deep-query pierces open roots):

await ml.agent("Read the Display name in the settings panel, then click 'Reveal access code' and report the access code that appears.")

Try (CLOSED mode) — host.shadowRoot is null, so no selector reaches inside. A correct agent should say the content is in a closed shadow root and it can't read it by selector (it could still click by coordinate via ml.locate/@pt, since a click retargets into the closed tree — but it must never claim to have read sealed text):

await ml.agent("Read the Display name in the settings panel and report the access code.")
