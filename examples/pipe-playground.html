Pipe Playground

A long, structured document (a fake CHANGELOG) for exercising fetch_url's pipe option — the small, safe grep · head · tail · wc · sort · uniq line-scanner. The point: instead of reading this whole page into context, the agent fetch_urls it and pipes it down to the handful of lines it needs.

⚠ Open me over http, not file:// — fetch_url only fetches http(s) URLs. Run cd examples && python3 -m http.server 8000 and visit http://localhost:8000/pipe-playground.html.

Try (the agent fetches THIS page as Markdown, then pipes it — the queries match the version headings + dates, which these instructions can't accidentally match):

  • "How many releases are in the changelog?" → pipe: "grep '^## ' | wc -l"
  • "List the 3 newest releases." → pipe: "grep '^## ' | head -3"
  • "What's the OLDEST release date?" → pipe: "grep -oE '202[0-9]-[0-9][0-9]-[0-9][0-9]' | sort | head -1"
  • "How many releases per month?" → pipe: "grep -oE '202[0-9]-[0-9][0-9]-' | sort | uniq -c" (the classic frequency count)

For anything the dialect can't express, the tool tells the model to drop to exec: const { markdown } = await ml.fetch(url) and process the string in JS.
